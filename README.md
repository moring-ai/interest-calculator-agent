# interest-calculator-agent

The agent, its tools, and the infrastructure that deploys both to AWS.

This repository owns **all the math**. The companion repository,
[interest-calculator-interface](https://github.com/moring-ai/interest-calculator-interface),
owns the UI and API and reaches everything here over the network — it never
imports this code.

---

## The core idea

**The language model never does arithmetic.**

Compound interest, amortization schedules and capital-gains brackets are
deterministic. A model computing them produces numbers that look right and
sometimes are not, and there is no way to unit-test a model's mental math. So:

| Layer | Responsibility |
|---|---|
| `packages/finance_core` | Every number. Pure Python, no I/O, tested against published formulas. |
| `packages/rate_feed` | Every live rate, tagged with source, date and freshness. |
| `packages/interest_tools` | Composes the two into `{summary, charts, assumptions, citations, notes}`. |
| `mcp_server` | Exposes those as MCP tools. |
| `agent` | Understands intent, picks a tool, explains the result. Computes nothing. |

## Architecture

```
AgentCore Runtime (Container, ARM64)
  Strands agent
    ├─► Bedrock            model inference
    └─► MCP over HTTPS ──► EC2 t4g.small
                             Caddy (TLS + bearer auth)
                               └► ToolHive (thv)
                                    └► MCP server container
                                         └► finance_core
```

Everything is in `us-east-2`.

## Layout

```
packages/           finance_core, rate_feed, interest_tools (+ 57 tests)
mcp_server/         FastMCP server + Dockerfile
agent/              Strands agent, Dockerfile, runtime IAM policy
agentcore/          AgentCore project config and CDK scaffolding
infra/toolhive/     Terraform: VPC, EC2, ECR, IAM, SSM, cloud-init
scripts/            env.sh (TLS), deploy-mcp.sh
```

## Setup

```bash
uv venv .venv --python 3.12 && uv pip install --python .venv/bin/python \
  -e packages/finance_core -e packages/rate_feed -e packages/interest_tools \
  pytest httpx "mcp~=1.24.0"
```

```bash
.venv/bin/python -m pytest packages/ -q
```

57 tests. They assert against hand-computed values from published formulas and
the 2026 IRS tables, not against a previous run of this code.

## Running the MCP server locally

```bash
.venv/bin/python mcp_server/server.py
```

Serves streamable-HTTP MCP on `http://127.0.0.1:8000/mcp`. Set `FRED_API_KEY`
for live rates; without it every rate is clearly labelled `SYNTHETIC`.

## Deploying

**Tool server** — builds the ARM64 image, pushes to ECR, restarts the service:

```bash
./scripts/deploy-mcp.sh
```

**Infrastructure** — first time, or after changing `infra/toolhive/`:

```bash
cd infra/toolhive && terraform apply
```

`terraform output mcp_url` gives the endpoint; `terraform output -raw mcp_token`
gives the bearer token. Both are what the interface repo needs in its `.env`.

**Agent**:

```bash
source scripts/env.sh && agentcore deploy -y
```

```bash
agentcore invoke "What's the 30-year mortgage rate?"
```

## Design notes

**Why ToolHive needs an EC2 instance.** ToolHive spawns MCP servers as
containers, so it needs a container runtime. Fargate does not offer
Docker-in-Docker, which rules it out; the alternatives are a VM or Kubernetes,
and a `t4g.small` is far cheaper than an EKS cluster for one server.

**`thv run` must be foregrounded under systemd.** Without `--foreground` it
returns immediately and leaves the proxy as a detached child, which systemd
kills along with the rest of the unit's cgroup. The workload stays registered
but dead, nothing listens on 8080, and Caddy answers 502.

**Do not read `MCP_HOST` in an MCP server.** ToolHive injects
`MCP_HOST=127.0.0.1` into every workload it runs. A server that honours it binds
to the container's own loopback where ToolHive's ingress proxy cannot reach it —
the container reports healthy and every request still fails. This server reads
`MCP_BIND_HOST` instead.

**The `ic-payload` channel.** LiteLLM's AgentCore adapter reads only
`event.contentBlockDelta.delta.text` and drops every other event shape, so tool
results sent as their own event type never reach the interface. The agent
therefore emits each result as a fenced ```` ```ic-payload ```` block inside its
text. It is built by **agent code, not by the model** — a model cannot be relied
on to reproduce kilobytes of JSON verbatim, and one mangled character costs the
whole chart.

**Auth.** Caddy checks a bearer token generated by Terraform and stored in SSM.
The agent's execution role reads that parameter at startup, so the secret is
never committed — `agentcore.json` holds only the parameter's *name*. ToolHive
supports OIDC when per-client identity is wanted.

## Limitations

- Savings APY is estimated from the federal funds rate when not supplied; no
  free per-bank APY feed exists.
- Tax figures are **federal estimates only** — no AMT, no loss carryforwards,
  state handled as a flat rate.
- Not financial, investment, or tax advice.
